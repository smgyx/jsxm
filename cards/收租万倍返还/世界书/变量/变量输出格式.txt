变量输出格式:
  rule:
    - 整条回复只能有一个 UpdateVariable 块，放在正文全部写完之后、状态栏占位符 <StatusPlaceHolderImpl/> 之前
    - 补丁按 JSON Patch 写法，只能用 replace、add、remove、move。不要用 delta、insert
    - replace 只能改已经存在的路径。新红颜、新NPC、新产业、新道具用 add。删掉用 remove
    - 女性角色只进红颜，其他人物只进 NPC，禁止两边各写一份
    - 下划线开头的字段（系统_）只读，不要改
    - 玩家消息含「【接手登记】」时，必须 replace 这七条已有路径：/主角/基本信息/姓名、/主角/基本信息/年龄、/主角/基本信息/性别、/主角/基本信息/身高、/主角/基本信息/体型、/主角/基本信息/外貌、/主角/基本信息/衣着。年龄写成数字。消息里没写的项保持林野默认，不要留空
    - 玩家消息以「按林野来」开头，或开场还没自定义时：这七项保持林野默认，不要改写成别人
    - 以上两种开局消息当轮，都必须 replace /主角/已登记 为 true。此后不要再改已登记
    - 禁止改 /世界/剧情节点/当前事件 和 /世界/剧情节点/下一个事件
  format: |-
    <UpdateVariable>
    <Analysis>
    - 本轮是不是「【接手登记】」或「按林野来」。是的话，七项身份怎么处理，已登记必须写成 true
    - 本轮经过的时间，以及是否允许大额结算
    - 对照每条 check，只根据本轮正文判断哪些字段变了
    - 新登场的女性角色是否已用 add 完整建档进红颜；新人物是否收录进 NPC
    - 数字写清：旧值 + 变化 = 新值
    </Analysis>
    <JSONPatch>
    [
      { "op": "replace", "path": "/主角/已登记", "value": true },
      { "op": "replace", "path": "/世界/时段", "value": "傍晚" },
      { "op": "add", "path": "/NPC/周克梅", "value": { "身份": { "相亲对象": "母亲介绍的相亲" }, "关系": { "相亲": "第一次见面" } } },
      { "op": "replace", "path": "/选项", "value": ["离开包间"] }
    ]
    </JSONPatch>
    </UpdateVariable>

  /选项 必须整组替换成恰好 1 个不超过 20 字的下一步。它必须是当前事件的下一节点，不是摘要。真没有可给的行动时才写成空数组。上面的例子只说明写法，值要按本轮正文换，不要照抄。
